# Wireframe 驗證與比對工作流

本工作流旨在檢查 `docs/features/{功能模組名}/wireframes/` 下的設計檔案，比對已敲定的商業需求 (BRD) 與產品需求 (PRD)，確保沒有漏掉任何頁面，且操作動線和功能邏輯相互吻合。

## 執行步驟：

### 1. 嚴格確認檢查項目名稱
- 因為 `docs/features/{功能模組名}/` 與 `docs/features/{功能模組名}/` 下可能包含多個專案文件，**使用者必須明確提出要檢查的「項目名稱」**（例如：`example_module`）。
- **【重要】** 若使用者未提及明確的項目名稱，請立即暫停工作流，並向使用者反問要求提供名稱。

### 2. 讀取基準需求文件
- 根據確認的項目名稱，讀取其對應的 BRD 與 PRD 文件：
  - BRD 路徑：`docs/features/{功能模組名}/<項目名稱>_BRD.md`
  - PRD 路徑：`docs/features/{功能模組名}/<項目名稱>_PRD.md`
- 提取並列出文件中所定義的核心功能清單、使用者動線 (User Flow) 及應具備的頁面。

### 3. 比對 Wireframe 檔案 (啟動 UIUX/UIUX 設計師)
- 引用 `uiux` Skill。
- 檢視 `docs/features/{功能模組名}/wireframes/` 底下與此項目相關的設計檔案（例如 `.drawio` 或其他可讀文件）。
- 執行雙向比對：
  1. **缺頁檢查 (Missing Pages)**：PRD 指定的頁面、組件（如彈窗、錯誤提示）是否在 Wireframe 中遺漏？
  2. **衝突檢查 (Conflicts)**：Wireframe 中的按鈕佈局、欄位或跳轉邏輯，是否與 BRD/PRD 描述的意思相左或發生衝突？

### 4. 產出驗證報告
- 將上述的比對結果詳細記錄。
- 在 `docs/features/{功能模組名}/wireframes/` 目錄下建立一份驗證報告，檔名格式為 `<項目名稱>_Wireframe_Validation_Report.md`。
- 報告內容應包含：
  - 本次檢查的範圍與讀取的檔案清單。
  - **遺漏頁面與功能清單**。
  - **需求與設計的衝突點分析**。
  - **UI/UX 優化與修正建議**。

### 5. 總結回報
- 在對話中向使用者回報驗證流程已結束，並簡潔有力地點出報告中最嚴重的衝突或缺失，引導使用者去閱讀產出的驗證報告檔案。
