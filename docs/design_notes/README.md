# 設計筆記 (Design Notes)

**DN 是開單前置關卡，不是待辦清單。**

當 scrum-master 當場寫得出可驗收的 AC，就直接開工單——**不要開 DN**。
只有在寫不出來的時候（方案沒定、邊界不清、影響範圍未知）才先開一份 DN。

| 情境 | 動作 |
|---|---|
| 當場寫得出可驗收的 AC | 直接開工單 |
| 寫不出來 | 先開 DN |

一句話：**DN 是 AC 難產時的緩衝區。** 進場與畢業共用同一個測試——
「寫得出至少一張工單的 AC 了嗎」。

完整規範（狀態、畢業條件、畢業去向分類、與權威階序的關係）見
[`../standards/documentation_conventions.md`](../standards/documentation_conventions.md)。

## 開一份新的

1. 取號——全域流水號，接續目前最大值：

   ```bash
   ls docs/design_notes/DN-*.md 2>/dev/null | sed 's/.*DN-\([0-9][0-9]*\)_.*/\1/' | sort -n | tail -1
   ```

   輸出是**目前最大號**，下一份就是它加一；**沒有輸出代表還沒有任何 DN，從 `DN-001` 開始**。

   ⚠️ **取號只認檔名，不掃檔案內容。** 掃內容的版本
   （`grep -rhoE "DN-[0-9]+" docs --include=*.md`）會撈到行文裡提及的號碼——
   agent-team-kit 自己實測過：某張工單內文提到的測試 fixture `DN-099` 讓它回 `DN-099`，
   照做的人會開出 `DN-100`。**縮小掃描範圍解決不了**，因為 DN 自己也會在行文裡引用別的號碼。
   編號本來就編碼在檔名裡，從檔名取才不會被污染。

   `[0-9][0-9]*` 是刻意的可攜寫法，別「簡化」回 `\+`——後者是 GNU 擴充，
   BSD sed（macOS 預設）不匹配，會原樣吐出整條路徑而不是編號。

2. 複製 [`_TEMPLATE.md`](_TEMPLATE.md) 成 `DN-0XX_短描述.md`（小寫底線）。
3. 填 header 五個欄位，**來源必填**。

## 為什麼全域扁平、不放模組底下

DN 存在的前提就是「**還不知道它屬於哪個模組**」——真知道的話早就開工單了。
先放模組底下，等於在最不確定的時候逼自己做一個歸屬決定，之後幾乎一定要搬檔案。

全域流水號的理由同 ADR：多套並行編號會產生編號衝突，而衝突發生時
既有連結已經散落在工單、commit 訊息與其他 DN 裡，修不回來。

## 這個目錄的其他約定

- **要圖就用 Mermaid 內嵌**，不開附件目錄。每份 DN 永遠是單一檔案，
  不必為「有附件的 DN」發明第二種形狀。
- **已畢業／已放棄的 DN 不刪、不搬、凍結唯讀。** 它記的是被否決的選項與否決理由，
  刪掉就永遠回答不了「當初為什麼不用 X」；搬目錄會弄斷既有連結。
- **推翻一份已畢業的 DN，要開新 DN**，舊的標 `Superseded by DN-0YY`，不要改舊檔。
- **索引不手動維護。** 不要在這裡放一份「DN 一覽表」——手抄的索引一定會出現孤兒。
