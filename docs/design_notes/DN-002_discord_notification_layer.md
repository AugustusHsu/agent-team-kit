## 1. 問題陳述

目前所有需要使用者介入的時刻，都要靠使用者**主動回來看**才會發現：

- Icebox / DN 停在 `Exploring` 沒人回頭處理
- 工單卡在 `In Review` 等簽核
- 執行前的 HITL 確認（`team_protocol.md` §1.7）
- 矛盾暫停（§1.2）發生時的裁定

這正是最初的抱怨——「整體流程都會因為我需要允許或是看過卡住」。
問題不只是「要等你」，而是**你不知道有東西在等你**。

## 2. 已知的邊界條件

- **只推「只有你能決定」的那一類**。機械可判定的走 CI，需要判斷但不必是你的走 AI 審查。
  推得太多等於沒推——通知一旦變成噪音就會被靜音。
- **停滯偵測歸這裡**。它**不得**寫進 `BACKLOG.md`：納入版控的生成檔必須是輸入的純函數，
  嵌入「停滯 N 天」會讓同一份 repo 在不同日期產出不同檔案（詳見 DN-001 §5）。
- **不阻塞在本 DN 上**。停滯偵測的計算本身很便宜，可以先做成
  `scan_backlog.py --stale`（只印 stdout、零寫入）。Discord 是升級，不是前提。
