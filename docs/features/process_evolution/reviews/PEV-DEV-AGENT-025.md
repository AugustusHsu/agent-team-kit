## 3. AC-02：量化驗證，以及一個工單沒預期到的發現

工單假設「現有 5 份各自寫了貼合自身的一句」，只要新的 8 份不互相抄就好。
**實測推翻了這個假設。**

`verify_ac02.py` 的判準：抽出每份的 §1.12 段落，扣掉共用的 canonical 引用字串、
去掉標點，兩兩取最長共同子字串。

**第一次跑**：`backend-developer` ↔ `frontend-developer` 共同子字串 **75 字**——
兩份的 §1.12 段落除了角色名以外**逐字相同**。這是先前工單留下的複製貼上，
不在本工單列出的三筆脫節裡，是驗證時才浮出來的。兩份都已改寫成各自的論點：

| 角色 | 改寫後的論點 |
|---|---|
| backend-developer | §1.12 的無提示失效是「表格塌成 JSON 陣列」，**而後端本來就預期看到 JSON**——其他角色至少還有「這東西長得不對」的違和感，後端連那個都沒有 |
| frontend-developer | 唯一**正確答案是視覺**的開發角色：畫面必須先被轉述成文字才進得了 context，那一步本身已經有損；通道再失真就是兩層疊加，而手上沒有第三份原件可對照 |

**第二次跑**：最長共同子字串 **17 字**，超過 12 字門檻的仍有 7 對。逐對檢視：

| 長度 | 內容 | 判定 |
|---|---|---|
| 17 | `- **確認你查到的是原文**：查閱檔案或判讀…` | **條目標題**，刻意跨角色一致 |
| 14 | `最嚴重的那種失效不留任何提示` | §1.12 規則原文的複述 |
| 14 | `判讀測試輸出前，先依…做開工自檢` | 指令句型 |

**判定通過**：重疊的全部是「規則本身怎麼說」與「條目叫什麼名字」，
**沒有任何一對共用「為什麼這條對我這個角色特別危險」的論證**——而後者才是 AC-02 要防的東西。

⚠️ **12 字這個門檻是我自己在寫檢查時訂的，看到結果後沒有調降它**。
留著超標紀錄比改門檻誠實：下一位重跑 `verify_ac02.py` 的人會看到同樣的 7 對，
而不是一份被調整過所以「全綠」的報告。

**8 份新增的論點各自是什麼**（證明不是套模板）：

| 角色 | 切入點 |
|---|---|
| business-analyst | BRD 的骨架是「ROI 數字 ＋ 痛點論證」，兩者存活率天差地遠——數字結構化最容易原樣通過，論證是散文最容易整段消失；留下漂亮數字卻失去來歷，而決策者買單的正是來歷 |
| product-manager | PRD 是下游三方施工與測試的唯一藍圖，**上游角色的取證失誤會被整條下游放大** |
| qa-test-planner | 「追溯覆蓋率 N / M」是衍生數字，矩陣被折疊時分母 M 變小、覆蓋率**會往上跑**——失真在這裡不會讓數字變難看，只會變好看 |
| scrum-master | BACKLOG 同步用的指令輸出**走的是 shell**；統計摘要被改寫時，錯的不是一張表，是全專案對自己進度的認知 |
| security-engineer | 工作介面是勾選清單，而「這項沒勾」與「根本沒有這一項」會塌成同一個樣子——**別人漏讀一格是重工，資安漏讀一格是把未防禦的面判成已通過評審** |
| system-architect | **留下的是結論、消失的是理由**——會看到「選 Golang」，看不到「為什麼不是 Node.js」 |
| tech-lead | Mermaid 少掉一條關聯之後**仍然是語法合法的 Mermaid**，不會有任何錯誤提示 |
| uiux | wireframe 是 **ASCII-art**，資訊全在空白與換行的相對位置上 |

## 7. 僅人工判讀、沒有機器把關的部分

1. **8 句新增內容的「貼合度」**。`verify_ac02.py` 只能證明彼此不同，
   **不能證明每一句對那個角色是真的成立**。這一點有實證教訓：我第一版寫的 3 句
   引用了不存在的檔案內容（說 qa-test-planner 的矩陣缺口是「空格」，實際是 `❌ 未覆蓋`／`—`；
   說 BA 的 As-Is 是對照表，實際是流程圖；把功能清單說成在 BRD，實際在 PRD）。
   三句都是逐份開檔比對後才發現並改掉的——**寫「貼合角色的一句」時，
   最容易錯的正是對那個角色的想像**。
2. **正規化後的寫法是否是最好的寫法**。全路徑形式（`.agent/resources/team_protocol.md`）
   比裸檔名長，代價是每處多 24 字元 × 53 處。判斷依據是指路檔造成的真實歧義（§2），
   但「值不值得」是人工權衡。
3. **本張沒有新增任何測試**，135 這個數字本輪不變。也就是說
   **§1.12 覆蓋 13 / 13 這件事今天成立，明天新增第 14 份 skill 時不會有任何東西提醒**——
   這正是 `PEV-DEV-AGENT-026` 存在的理由，在它落地前，這份對齊是靠人維持的。
