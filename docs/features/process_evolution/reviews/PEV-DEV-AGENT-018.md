### 3. 負向對照（破壞實作，確認測試真的抓得到）

只證明「壞的輸入會紅」不夠——那只說明檢查器有反應。還要證明**實作被改壞時測試會紅**，
否則測試可能只是在陪跑。三種改法：

| 改法 | 選中 | 轉紅 | 說明 |
|---|---|---|---|
| `strip_code` 直接 `return text`（不剝程式碼） | 3 | **2** | 兩支假紅燈迴歸轉紅。第三支（行號對齊）不受影響是**正確的**——identity 函式同樣保持行數，它守的是另一個性質 |
| 時間戳一律當 datetime 比（不降日期粒度） | 1 | **1** | `2026-01-02` 被當成午夜 00:00，判成早於 `2026-01-02T14:06` |
| 四項檢查加上 `break` 短路 | 1 | **1** | `❌` 只剩 1 個 |

還原後 `diff -q` 確認原始碼與備份逐位元相同。

### 4. 設計判斷

**沿用而非重寫**：`precheck.py` 直接 `import scan_backlog`，取用 `find_project_root()`、
`scan_all_tasks()`、`format_backlog_markdown()`、`STATUS_ICONS`、`TZ_TAIPEI`。
重寫一份 metadata 正則就是保證 drift——而 `PEV-DEV-AGENT-012` 剛修好的跨行 bug
正是那份正則。Status 合法值也因此只有一個定義處。

**兩個假紅燈是規劃期實查發現的，不是實作時猜的**：

- `PEV-DEV-AGENT-001` 的 `Closed` 是純日期、`Created` 有時分。純日期是合法 ISO 8601，
  精度較粗的值推不出先後違規。
- `PEV-DEV-AGENT-008.md:89` 的 `[DN-007](DN-007_ci_gate.md)` 包在反引號裡，
  是被引用的例子。這個盲點也是 `PEV-DEV-AGENT-016` 當初被迫把範例路徑寫成
  非連結語法的原因。

假紅燈比漏抓更值得防：漏抓只是沒幫上忙，假紅燈會**逼作者改成不自然的寫法來閃避檢查**，
等於讓工具反過來污染文件。
