## 1. 問題的形狀

模板的診斷是對的、藥開錯了。舊範例的最後一行是：

```
格式見 `.agent/workflows/commit-message.md`。
```

**它把「規則」換成了「規則的地址」**，而模板前一段自己剛講完那個地址不會被走到
（`/commit-message` 沒被呼叫時不載入）。指路成功、規則沒送達。

本 repo 就是受害者：`CLAUDE.md` 忠實照抄，於是整批歷史 commit 的 Body 寫成散文，
而 `commit-message.md:78` 要求的是 `- **標題**：說明`。**沒有任何一次 commit 讀到那條規則。**

這是模板類缺陷裡槓桿最大的一種：**錯一次，每個裝了 kit 的專案都跟著錯**，
而且不會有任何執行期訊號。

### ⚠️ 對照 4 的結論是「區塊擷取目前不吃重」

`PEV-DEV-AGENT-002` 剛踩過一個坑：整份檔案做子字串比對，會被正文別處的順口提及遮掉。
本單一開始就照那個教訓寫了 `partition("```markdown")` 的區塊擷取。

對照 4 想證明它是必要的，**結果證明了相反**：`- **標題**：說明` 在
`kit/CLAUDE.md` 全檔只出現 1 次（就在範例裡），所以掃整份檔案一樣抓得到。
**區塊擷取現在是預防性的，不是 load-bearing 的。**

保留它的理由是：模板未來很可能在正文裡舉例說明那個格式（就像 002 那次那樣），
屆時整份掃描就會失效，而失效的形式是**安靜地變綠**。這裡先付掉那三行成本。
如實記下這一項，是為了不讓下一個讀的人以為對照 4 證明了它不可或缺。

## 4. 廢除舊規則的登記

依 repo 慣例，推翻流程規範要在 `已廢除的流程規則` 加一列。本單廢除兩樣東西，
用同一個 pattern 抓：

```python
r"寫\*\*三行以內\*\*|^格式見 `\.agent/workflows/commit-message\.md`。$"
```

- 前半抓長度紀律的舊值。
- 後半抓「範例最後一行只有地址」這個形狀——`^…$` 錨定整行，
  所以正文裡引用同一個路徑（模板本文就有兩處）不會誤判。

`PEV-DEV-AGENT-011` 的 AC 也寫著「維持**三行以內**」，但它已結案，
依 §1.11「不改它，也不引用它」不動；該表只掃 `kit/`，不會誤觸。

## 5. 種子檔的處理

`CLAUDE.md` 在 `is_seed_file()` 名單裡，`./install.sh . --upgrade` **不會**把模板的
新版推到根目錄那份——這正是設計意圖（安裝後歸專案自己維護）。所以本 repo 的
`CLAUDE.md` 是**手改**的。

驗證：`./install.sh . --upgrade --dry-run` → 「新增 0、更新 0、已是最新 60、保留 4、待合併 0」，
`kit/CLAUDE.md` 改動後計數不變，證實它落在「保留」而非「待合併」。

⚠️ **這代表既有安裝不會自動拿到修正。** 已經裝了 kit 的專案，其 `CLAUDE.md` 仍是舊的
只指路版本，必須人工比對模板才會更新。這是種子檔機制的固有代價，不是本單的缺陷；
要不要為種子檔提供「模板改了，來看一下」的提示，屬於升級機制的議題，本單不擴張。

## 6. 沒做的事

  屬於第 2 層。本單能保證的是規則進到了每次請求都載入的檔案裡。
