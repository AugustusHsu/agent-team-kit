## 1. 任務描述 (Description)

`scan_backlog.py` 解析工單 metadata 的六條正則，值前面的分隔用的是 `\s*`。
**`\s` 包含換行**，所以欄位留空時正則不會失配，而是跨行往下找到第一個非空白字元，
把**下一行整行**當成這個欄位的值。

客觀重現（本工單開單前實測）：

```python
p = re.compile(r"\*\*✅\s*完成時間\s*\(Closed\):\*\*\s*(.+)$", re.MULTILINE)
doc = "**✅ 完成時間 (Closed):**\n**🔀 審查載體編號 (PR/MR):** —\n"
p.search(doc).group(1)   # → '**🔀 審查載體編號 (PR/MR):** —'
```

Closed 留空是**進行中工單的正常狀態**（`_TEMPLATE` 給的就是空值），因此這不是邊角案例，
而是每一張未結案工單都會踩到。影響：

- `closed` 欄位被灌進垃圾值，JSON 輸出與 BACKLOG 的「完成時間」欄顯示成別行的內容
- 下游任何 `if task["closed"]` 的判斷都會誤判成「已有完成時間」
- 六條欄位正則全部有同樣的形狀問題，Closed 只是最常留空的那一條

對照組：同一支腳本的 `DN_STATUS_RE`／`DN_DEPENDS_RE` 寫的是 `^...\s*(.+?)\s*$`，
有行首錨點，比欄位正則更保守——修法就是把欄位正則對齊到同樣的嚴謹度。

## 2. 規格：輸入與輸出 (Inputs & Outputs)

**輸入**：`kit/.agent/scripts/scan_backlog.py` 的 `PATTERNS` 字典（六條欄位正則）。

**輸出**：正則只吃**水平空白**，不跨行。

| 情境 | 修正前 | 修正後 |
|---|---|---|
| `**✅ 完成時間 (Closed):** 2026-08-17T16:40+08:00` | 該值 | 該值（不變） |
| `**✅ 完成時間 (Closed):**`（空值，後面還有內容） | 下一行整行 | `None` |
| `**✅ 完成時間 (Closed):**` 後接空行 | 再下一個非空白行 | `None` |
| 欄位整條不存在 | `None` | `None`（不變） |

作法：把 `\s*` 換成 `[^\S\r\n]*`（水平空白），並補上 `^` 行首錨點與 `\s*$` 前的收尾，
與 `DN_STATUS_RE` 的寫法一致。空值走「不匹配 → `None`」這條既有路徑，
`parse_task_file()` 的 `else: result[key] = None` 不必改。

### 修法說明與一處超出描述的收緊

正則改成 `rf"^\*\*…{_H}(\S.*?){_H}$"`，其中 `_H = r"[^\S\r\n]*"`（只吃水平空白）。
除了工單描述講的「`\s*` → 水平空白」，另外做了兩處收緊，都是為了讓空值確實走到「不匹配 → `None`」：

1. **補 `^` 行首錨點**——與同檔既有的 `DN_STATUS_RE`／`DN_DEPENDS_RE` 寫法一致，
   避免 metadata 標記出現在內文中段時被誤認。工單 metadata 本來就寫在行首，行為不變。
2. **值改為 `(\S.*?)` 而非 `(.+?)`**——第一版只把 `\s*` 換成水平空白，
   遇到 `**✅ 完成時間 (Closed):**   `（冒號後只有空格）時 `(.+?)` 會吃掉一個空格，
   `strip()` 後得到 `''` 而不是 `None`。要求首字元非空白才能一致回到 `None`。

七種輸入的實測結果（有值／空值+下行有內容／空值+空行／空值+尾隨空白／欄位不存在／
值有尾隨空白／值含空格與括號）全部符合工單「規格：輸入與輸出」那張表。
