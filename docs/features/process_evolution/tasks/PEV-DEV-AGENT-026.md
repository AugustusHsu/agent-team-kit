## 1. 任務描述 (Description)

[DN-004](../../../design_notes/DN-004_skill_system_realignment.md) §4 待決 4.5 的落地，
使用者裁定**採用 B ＋ A+**。這是 DN-004 唯一「防未來」的產出——4.1～4.4 都是一次性修補，
只有這一項會持續生效。

**兩條檢查**：

| 檢查 | 內容 |
|---|---|
| **B：適用角色覆蓋率** | 規範中標「**適用全角色**」的章節（目前只有 §1.12），必須被 13 份 skill 全部引用 |
| **A+：引用編號＋標題比對** | skill 內的 `team_protocol.md §X.Y 標題` 引用，編號要存在**且**標題要對得上真實 `### X.Y` 標題 |

**為什麼不是原本提的檢查 A（只比編號）**：DN-004 §4 附錄用丟棄式原型實跑推翻了它。
A 對現況命中 0 筆；在「§1.9 後插入一節、1.10/1.11/1.12 各往下推一格」的重編號實驗中，
**4 筆 `§1.12` 引用當場指到「文檔權威階序」而非「取證通道保真」，A 仍然全綠**——
因為 `§1.12` 這個編號還在。編號幾乎總是還在，所以 A 實際只抓得到
「手誤打成不存在的節號」這一種低頻錯誤。同一實驗中 A+ 抓到全部 4 筆。

## 2. 規格：輸入與輸出 (Inputs & Outputs)

**輸入：** `kit/.agent/resources/team_protocol.md`、`kit/.agent/skills/*/SKILL.md`。

**輸出：** `tests/test_kit_integrity.py` 新增兩項測試。

**落點為什麼是 `tests/` 而不是 `precheck.py`**：沿用 DN-007 §3.2 對
「已廢除的流程規則殘留」那一項的裁定——其他 precheck 項目檢查的是
**使用者自己寫的工單與文件**，這兩條檢查的是 **kit 出貨內容有沒有被改壞**。
使用者專案不編輯 `.agent/`，帶著一份永遠綠的檢查沒有意義，那是假閘門。

**誤報緩解**：標題比對只取括號前的中文主體，忽略 `(🔬 Evidence Channel Fidelity)` 那段，
純修飾標題（加 emoji、補英文）不會轉紅。

## 5. 範圍外 (Out of Scope)

- **不做雜湊比對**（4.5 選項之一）：規範改一個錯字就要重算 13 份 skill 的雜湊，
  訊噪比太差。
- **不驗證「引用之後有沒有照做」**——兩條檢查都只驗證「有沒有引用」。
  這是已知且接受的限制（DN-004 §4 待決 4.5 的反方欄）。
- **前置依賴**：本工單必須在 `PEV-DEV-AGENT-025` 合併後才開始。
  先上檢查會讓 CI 立刻紅在半數 skill 不合規上。
